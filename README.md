## 💼 Por qué esto importa / Why this matters

**ES** — Un formulario que acepta lo que sea deja dos rastros: datos inservibles en tu base —correos inválidos, campos vacíos, texto donde iba un número— y una puerta abierta a envíos maliciosos. El problema aparece meses después, cuando una campaña rebota contra direcciones que nunca existieron o alguien encuentra lo que tus validaciones no filtraron.

Esta auditoría verifica **más de 50 comportamientos por campo** y registra con evidencia cómo responde el formulario ante cada uno. Cuando la evidencia no alcanza para afirmar que algo está protegido, no se da por bueno: el resultado dice lo que se comprobó, no lo que se supone.

**Si no eres técnico:** lo que importa es el informe. Cada corrida genera uno con la lista de qué se verificó, qué pasó y qué falta corregir.

**EN** — A form that accepts anything leaves two traces: unusable data in your database — invalid emails, empty fields, text where a number belongs — and an open door for malicious input. The problem surfaces months later, when a campaign bounces off addresses that never existed, or someone finds what your validation didn't filter.

This audit verifies **50+ behaviors per field** and records, with evidence, how the form responds to each. When evidence isn't sufficient to prove something is protected, it isn't assumed to be: the result states what was verified, not what is presumed.

**Not technical?** What matters is the report. Every run produces one listing what was verified, what happened, and what needs fixing.

## Setup

```bash
# 1. Install Node.js (>= 24.0.0)

# 2. Install dependencies
npm install

# 3. Install Playwright browsers
npx playwright install --with-deps chromium

# 4. Configure environment variables
cp .env.example .env
# Edit .env and fill in your values (URLs, credentials, etc.)
```

## Running the audit

```bash
npm test
```

## Options

| Variable | Default | Description |
|----------|---------|-------------|
| `HEADED` | `false` | Set `true` to see the browser window during the audit |
| `SLOWMO` | `0` | Milliseconds to slow down each action (useful for debugging) |
| `CI` | `false` | Set `true` on CI environments |
| `WORKERS` | `1` | Number of parallel browser workers (default is 1 for stability) |
| `PAGE_URL_*` | *(recorded URL)* | Override any page URL — see `.env.example` for variable names |

## Reports

The HTML report is generated at `reports/auditing/` once the tests complete.
Run `npm run test:report` to open the Playwright HTML report automatically.

## Debugging Failures

When a test fails, a trace file is saved in `test-results/`. Open it with:

```bash
npx playwright show-trace test-results/<test-name>/trace.zip
```

The trace viewer shows a full timeline of actions, network requests, and screenshots.

### Required Secrets

Add the following secret in GitHub repository settings (Settings → Secrets and variables → Actions):

- `PAGE_URL_LOGIN` (the URL of the page under audit — e.g. `https://www.saucedemo.com`)

### Viewing Results

1. Go to the **Actions** tab in GitHub
2. Click on the latest workflow run
3. Download the `audit-reports` artifact for the full HTML + Markdown audit report
