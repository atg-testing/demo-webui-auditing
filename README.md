## What's inside

- **Target system:** [saucedemo.com](https://www.saucedemo.com/) (public, industry-standard QA demo site)
- **Page audited:** `Login` — `#user-name` and `#password` fields
- **Audit engine:** full pipeline — DOM analysis, field classification, declarative rule checks, behavioral experiments (real payload injection per field), maturity-state inference, FQI/SMI scoring, HTML + Markdown reports
- **Test types:** 50+ behavioral checks per field — required-field enforcement, boundary lengths, SQL injection, XSS injection, Unicode/extended-Latin acceptance, type confusion, binary injection, and more
- **Philosophy:** fail-closed — the engine never assumes compliance when evidence is insufficient, so a low score here is a real finding about SauceDemo's login form, not a false positive
- **CI/CD:** GitHub Actions workflow included and active — running on every push and pull request, not just a config file waiting to be wired up

## Setup

```bash
# 1. Install Node.js (>= 24.0.0)

# 2. Install dependencies
npm install

# 3. Install Playwright browsers
npx playwright install --with-deps chromium

# 4. Configure environment variables
cp .env.example .env
# Edit .env and fill in your values (URLs, credentials, etc.)
```

## Running the audit

```bash
npm test
```

## Options

| Variable | Default | Description |
|----------|---------|-------------|
| `HEADED` | `false` | Set `true` to see the browser window during the audit |
| `SLOWMO` | `0` | Milliseconds to slow down each action (useful for debugging) |
| `CI` | `false` | Set `true` on CI environments |
| `WORKERS` | `1` | Number of parallel browser workers (default is 1 for stability) |
| `PAGE_URL_*` | *(recorded URL)* | Override any page URL — see `.env.example` for variable names |

## Reports

The HTML report is generated at `reports/auditing/` once the tests complete.
Run `npm run test:report` to open the Playwright HTML report automatically.

## Debugging Failures

When a test fails, a trace file is saved in `test-results/`. Open it with:

```bash
npx playwright show-trace test-results/<test-name>/trace.zip
```

The trace viewer shows a full timeline of actions, network requests, and screenshots.

## CI/CD

This isn't a dormant CI template — the workflow in this exact repo is live and firing on every change. The audit runs automatically on:
- Push to `main` or `develop` branches
- Pull requests to `main` or `develop`

Every commit pushed to this repository has triggered a real run — see the [Actions tab](https://github.com/Vanegas2020/demo-webui-auditing/actions) for the full history.

### Required Secrets

Add the following secret in GitHub repository settings (Settings → Secrets and variables → Actions):

- `PAGE_URL_LOGIN` (the URL of the page under audit — e.g. `https://www.saucedemo.com`)

### Viewing Results

1. Go to the **Actions** tab in GitHub
2. Click on the latest workflow run
3. Download the `audit-reports` artifact for the full HTML + Markdown audit report

> **Note for anyone browsing this repo:** you can watch this project's own CI runs (see the badge and link at the top), but you can't trigger a *new* run here — GitHub Actions only runs with secrets configured on this specific repo, and only for people with write access. To run it against your own target, fork or clone the repo and set up the secret above on your copy — or just clone it and run the audit locally (see [Running the audit](#running-the-audit)).
